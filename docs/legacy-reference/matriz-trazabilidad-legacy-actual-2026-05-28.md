# Matriz de trazabilidad legacy vs actual

Fecha de corte: 2026-05-28

Objetivo: marcar, pantalla por pantalla del ERP legacy, si la funcionalidad esta en la plataforma actual, si fue reubicada, si fue consolidada dentro de otra vista, si queda parcial por validar o si no se ve equivalente actual.

## Fuentes

- Capturas legacy: [legacy-screenshots.md](./legacy-screenshots.md)
- Capturas actuales: [current-screenshots.md](./current-screenshots.md)
- Baseline por modulo: [baseline-modulos-legacy-vs-actual-2026-05-28.md](./baseline-modulos-legacy-vs-actual-2026-05-28.md)

## Leyenda

| Estado | Lectura |
|---|---|
| Esta | La funcion existe en la plataforma actual y se ve o se confirma en la vista/codigo revisado. |
| Esta / mejorado | Existe y ademas agrega trazabilidad, seguridad, integracion, exportacion o control superior. |
| Reubicado | Existe, pero ya no esta como pantalla independiente; se movio a otra ruta, pestana o flujo. |
| Reubicado / mejorado | Fue movido y ademas mejora el comportamiento legacy. |
| Consolidado | Varias pantallas legacy se resuelven ahora en una vista actual con filtros, tabs o busqueda central. |
| Parcial / validar | Hay base actual, pero falta confirmar si el control visible satisface exactamente el uso legacy. |
| No visible actual | No se encontro control/pantalla equivalente en las capturas actuales; debe tratarse como brecha candidata si el cliente lo usa. |

## Brechas candidatas a revisar antes de corregir

Estas no se marcan automaticamente como desarrollo pendiente hasta validarlas con uso real del cliente, pero son los puntos donde el legacy tenia una vista especifica y la captura actual no muestra un equivalente igual de directo:

- Caja: busqueda dedicada por documento + numero, busqueda dedicada por numero interno y listado aislado de boletas.
- Bodega inventario: vista visible de codigos de barra repetidos.
- Bodega taller: vistas visibles de codigos de barra repetidos, codigos internos repetidos, sin codigo barra, sin codigo interno, sin categoria y sin proveedor.
- Venta web: confirmar si el cliente necesita filtro de fechas directamente en OC Online o si basta Matriz Ventas.

## Regla para el siguiente sprint

Antes de implementar cambios, cada brecha debe convertirse en criterio de aceptacion: campo/filtro exacto, ruta donde debe aparecer, columnas esperadas, permisos y prueba funcional. Si el cliente acepta que una funcion esta reubicada o consolidada, no se replica la pantalla legacy como copia cosmetica.
